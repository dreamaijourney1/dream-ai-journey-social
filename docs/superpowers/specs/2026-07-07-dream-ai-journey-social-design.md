# Dream AI Journey — Automated Social Media Posting System

**Date:** 2026-07-07  
**Status:** Approved  

---

## Overview

A fully automated system that generates and publishes 21 social media posts per week (7 days × 3 platforms) for Dream AI Journey — a business that helps small businesses automate data entry, follow-up emails, AI chatbots, marketing automation, invoicing, billing, and inventory alerts. Posts are written by Claude, illustrated by DALL-E, and published directly to Facebook, Instagram, and Twitter/X via their native APIs. The system runs on GitHub Actions at zero cost.

---

## Goals

- Generate 21 platform-adapted posts per week with zero manual effort
- Maintain a warm, human, organic tone — never sound like a generic ad
- Always include a CTA to dream-page.com
- Avoid content repetition week-over-week using a rolling history file
- Run entirely free using GitHub Actions + native platform APIs

---

## Architecture

Two GitHub Actions workflows handle the full pipeline:

**Workflow 1 — Monday Generator (8am EST / 13:00 UTC)**  
Runs once per week. Generates all content for the coming week and commits it to the repo.

**Workflow 2 — Daily Poster (10am EST / 15:00 UTC, Mon–Sun)**  
Runs every day. Reads today's entry from `queue.json` and posts to all 3 platforms.

## Content Strategy

### Service Rotation
Dream AI Journey's 7 services map to 7 days of the week (rotating in fixed order):

| Day | Service |
|-----|---------|
| Monday | AI Chatbots |
| Tuesday | Follow-up Emails |
| Wednesday | Marketing Automation |
| Thursday | Data Entry Automation |
| Friday | Invoicing & Billing |
| Saturday | Inventory Alerts |
| Sunday | General / Brand Story |

### Angle Variety
Each week, Claude reads the last 4 weeks of `history.json` to see which angles were used, then picks a different format. Available angles cycle through (but are not limited to):
- Client win / success story scenario
- "Did you know?" tip or stat
- Myth-busting ("You don't need a big team to automate X")
- Question-led engagement post
- Behind-the-scenes / how it works
- Pain point + solution
- Before/after comparison

### Platform Formats
For each of the 7 daily themes, Claude generates 3 platform-specific versions:

| Platform | Length | Notes |
|----------|--------|-------|
| Facebook | 150–200 words | Conversational, storytelling-friendly, ends with CTA |
| Instagram | 100–150 words + 5–10 hashtags | Visual-caption feel, warm tone, same CTA |
| Twitter/X | ≤240 characters | Punchy, human, direct link to dream-page.com |

Tone across all platforms: warm, human, organic. Never sounds like a generic ad.

## Image Generation

- **Model:** DALL-E 3 via OpenAI API
- **Quantity:** 7 images per week (one per daily theme, shared across all 3 platform posts that day)
- **Size:** 1024×1024
- **Quality:** standard (~$0.04/image, ~$0.28/week)
- **Style:** Warm, approachable imagery — small business owners, friendly workspaces, humanized technology. No cold corporate stock-photo aesthetics.
- **Image prompts:** Generated by Claude alongside the post content, tailored to each day's theme
- **Storage:** Images are downloaded from OpenAI's temporary URL and committed to `images/YYYY-MM-DD/` in the repo, giving them permanent public GitHub URLs needed for Instagram's Graph API

---

## Platform Posting

### Twitter/X
- API: Twitter API v2 (free tier — 1,500 tweets/month write access; we use ~31/month)
- Auth: OAuth 1.0a (required for media upload)
- Flow: Download image from GitHub → upload to Twitter media endpoint → create tweet with `media_id`

### Facebook
- API: Meta Graph API (free for pages you own)
- Auth: Long-lived Page Access Token stored as GitHub Secret
- Flow: POST to `/{page-id}/photos` with image URL (GitHub raw URL) + caption

### Instagram
- API: Instagram Graph API (requires Instagram Business or Creator account linked to a Facebook Page)
- Auth: Same long-lived token as Facebook
- Flow: POST to `/{ig-user-id}/media` with `image_url` (GitHub raw URL) + caption → POST to `/{ig-user-id}/media_publish` with the returned `creation_id`

## Data Files

### `queue.json`
Generated every Monday. Contains all 21 posts for the week plus posting status.

```json
{
  "week_of": "2026-07-07",
  "days": [
    {
      "date": "2026-07-07",
      "service": "AI Chatbots",
      "angle": "Client win scenario",
      "image_path": "images/2026-07-07/day-1.png",
      "posts": {
        "facebook": "...",
        "instagram": "...",
        "twitter": "..."
      },
      "posted": {
        "facebook": false,
        "instagram": false,
        "twitter": false
      }
    }
  ]
}
```

### `history.json`
Updated every Monday with the current week's themes and angles. Keeps a rolling 4-week window so Claude can avoid repetition.

```json
{
  "weeks": [
    {
      "week_of": "2026-07-07",
      "days": [
        { "service": "AI Chatbots", "angle": "Client win scenario" },
        ...
      ]
    }
  ]
}
```

## GitHub Secrets Required

| Secret | Purpose |
|--------|---------|
| `ANTHROPIC_API_KEY` | Claude API for content generation |
| `OPENAI_API_KEY` | DALL-E API for image generation |
| `TWITTER_API_KEY` | Twitter OAuth 1.0a |
| `TWITTER_API_SECRET` | Twitter OAuth 1.0a |
| `TWITTER_ACCESS_TOKEN` | Twitter OAuth 1.0a |
| `TWITTER_ACCESS_SECRET` | Twitter OAuth 1.0a |
| `FACEBOOK_PAGE_ID` | Target Facebook Page |
| `FACEBOOK_PAGE_TOKEN` | Long-lived Page Access Token |
| `INSTAGRAM_USER_ID` | Instagram Business Account ID |

> The built-in `GITHUB_TOKEN` provided by Actions is used for committing `queue.json` and `history.json` back to the repo — no additional PAT required. Note: GitHub Actions cron times are in UTC. 8am EST = 13:00 UTC (shifts to 9am EDT during Daylight Saving Time).

---

## Error Handling

- **Monday generator failure:** If Claude or DALL-E fails, the workflow exits without committing `queue.json`. The daily poster finds no data for that day and skips silently. No partial broken state is committed.
- **Daily poster — single platform failure:** If posting fails on one platform (e.g., Twitter rate limit), the other two platforms still attempt to post. The failed platform is left as `false` in `queue.json` for inspection.
- **All failures are logged** to GitHub Actions run logs, visible in the repo's Actions tab.
